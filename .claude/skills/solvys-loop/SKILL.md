# Solvys Loop

Operate a sprint from durable records instead of conversation memory.

Run the Solvys Ponytail Ladder (`factory/canon/ponytail-ladder.md`) before
writing any fix or automation: YAGNI, existing repo seam, standard library or
native platform, already-installed dependency, maintained OSS with lower
ownership cost, one line, then the minimum custom code.

work freely, work with an open mind, and explore all possible options; never jump to conclusions at the second or third blocker. Be innovative, take inventory of your skills

## Entrance

1. Pass the Factory entrance and read the project manifest, active Sprint Unit,
   approved Development Contract, latest receipt, and infraction ledger.
2. Load `LOOP.md`, `STATE.md`, `loop-policy.json`, `run-ledger.json`, budget,
   run log, and `gate.yaml` from protected project custody.
3. Apply the canonical directive in `factory/canon/agency-directive.md`.

## Run

1. Reconcile Spec Kit artifacts with the Development Contract.
2. Run the pinned Loop Engineering `doctor`, `sync`, cost, context, and gate
   checks when the tool is available. Record an exact unavailable-tool result
   when the local capacity or installation gate prevents it.
3. Inventory current repo truth, installed skills, CLI, in-app browser,
   provider API, approved OSS, and project precedents.
4. Execute one bounded contract task. Run its named check and record proof.
5. On failure, refresh external state and choose a materially different safe
   path. The same normalized failure twice enters repair mode. The third opens
   the circuit.
6. Allow a human handoff only for MFA, CAPTCHA, consent, cost, rights, secret
   issuance, client decisions, or irreversible actions, with evidence and the
   smallest human action.

Recurring loops stay report-only for seven days. An approved
`symphony-ready` ticket can return a branch, commit, PR, review comment, and
proof. Auto-merge and automatic deployment stay disabled.

## Context budget

Inject identifiers, paths, revisions, protected zones, proof rung, and open
infraction fingerprints. Reference detailed doctrine by path. Do not paste the
entire Factory handbook into each prompt.

## Proof

Return loop health, contract revision, distinct paths tried, circuit state,
checkpoint, exact proof rung, and remaining genuine gate. Never turn a lower
proof rung into a completion claim.
