# Forbidden Mindsets, Actions, And Design Sins

These are rejected by default because they repeatedly created avoidable pain.

## Forbidden Mindsets

- **Solution before problem:** naming a feature, library, sprint, or redesign before identifying the user pain and observable outcome.
- **Proxy worship:** treating a build, health flag, automation record, localhost page, preview shell, or release note as the live product.
- **Nearest-example bias:** copying the easiest precedent instead of retrieving the strongest accepted work and its failure history.
- **Memory as authority:** trusting old branch, route, layout, provider, deploy, or stack notes when current repo/runtime truth is cheap to inspect.
- **Library salvation:** assuming a component library fixes product state, data ownership, reliability, or design coherence.
- **Aesthetic democracy:** combining individually attractive choices that do not belong to one visual world.
- **Premature personalization:** changing an inspiration reference before faithful reconstruction reveals what actually makes it work.
- **Activity as progress:** counting thread setup, planning, tool discovery, checkpoints, or agent motion as a solved problem.
- **Polish as honesty:** using confident language to conceal unverified runtime state, degraded dependencies, or missing authority.

## Forbidden Actions

- Overwrite, reset, delete, or reformat unrelated dirty work.
- Invent, rotate, expose, or silently substitute credentials and production configuration.
- Deploy, publish, migrate production data, message external people, complete review issues, or create paid dependencies without the required authority.
- Use localhost or port 7777 as a frontend test, review, or acceptance surface.
- Add a UI field without tracing its backend contract, persistence, and consumer.
- Apply a dependency or visual migration across the product before a representative gallery, provenance record, protected-surface ledger, and rendered acceptance gate exist.
- Use broad mocks that replace the operating model; mock only the narrow unavailable boundary.
- Call a planning artifact implementation, a candidate branch deployed, a preview live, or a release installed.
- Create new work before auditing applicable `Awaiting Review` items and the current branch/worktree.
- Let an automation silently rewrite canon, delete storage, complete issues, or report success without evidence and bounded scope.
- Create a heavyweight internal checkout before selecting an execution lane and
  passing the capacity gate.
- Create a duplicate worktree because a tranche moved into a new session when
  an exact prepared workspace already exists.
- Route a frontend sandbox around its project ChatGPT Site, or leave required
  human review unopened when the Site needs visual or content review.
- Publish a placeholder, screenshot, marketing mockup, fake dashboard, dead
  control, invented data, or close-enough substitute as a 1:1 ChatGPT Site
  prototype or deployment receipt.
- Treat Plasmic as committed product source or production proof before TP's
  source-transfer decision, or mix concurrent human-owned Plasmic changes into
  the agent lane without TP's explicit choice.
- Manually delete an opened worktree instead of archiving the eligible task and
  allowing the conversation sweep to drive natural retention.
- Keep retrying a broken prototype or browser route without producing a handoff, target file, exact blocker, and stop condition.

## Forbidden Design Sins

The full anti-slop law in `AGENTS.md` is controlling. These Solvys-specific sins sit on top of it:

- Border soup, card grids used as default structure, nested cards, side-stripe/Kanban alerts, or backplates behind ordinary icon controls.
- Instant popups, drawers, panels, sheets, tabs, or state changes when a purposeful transition applies.
- Decorative motion, hover jumps, entrance opacity traps, motion without reduced-motion behavior, or controls that look interactive but do nothing.
- One-off icons, fake brand glyphs, invented customer marks, emoji chrome, or a global icon migration without representative proof.
- Replacing readable dense numerals with display type; Doto-style display digits do not belong in timestamps, compact KPIs, or calendar values.
- Glass spread across every surface, botched blur, halo shadow, uncontrolled glow, or using material to hide weak hierarchy.
- Rebuilding a source surface from memory when the implementation or rendered reference can be inspected.
- Personalizing a reference before the fidelity checkpoint, or shipping a reference clone without client-specific divergence.
- Copying one Solvys product's visual skin into every client instead of preserving the relevant product register.
- A technically clean page with no authored signature, no meaningful interaction, and no relationship to TP's art or home.

## Possibilities To Shoot Down

Reject the premise immediately when someone proposes:

- “It passed locally, so it is live.”
- “The automation exists in a registry, so it ran.”
- “The shell loads, so the integration works.”
- “The component is beautiful alone, so we can migrate all surfaces.”
- “A generic explanation is enough; we do not need the exact data path.”
- “We can add the field now and wire the backend later.”
- “The user probably meant the old branch/layout/provider.”
- “The app is released, so it must be installed.”
- “The user gave us inspiration, so an approximate version is fine.”
