# PR review record

Use this compact template in the existing project receipt. Never include secrets or customer message bodies.

- Sweep timestamp/timezone and authorized actions:
- Repository/account, PR URL, creation timestamp and age:
- Head repository/branch/SHA; target branch/current SHA; recovery references:
- Current product/version; manifesto and approval sources/revisions:
- Diff/commit pagination completeness; current-base comparison:
- Production source/deployment; dependency and operational evidence:
- Supersession/overlap analysis; older-PR deep review:
- Disposition and evidence-backed reason:
- Useful changes to extract and current destination, if mixed:
- Reviewer, independent verifier, coordinator; actual session identities:
- Repair owner/environment, protected zones and final reviewed SHA:
- Required checks, user-journey proof, deployment trigger and rollback:
- Pre-mutation refresh, drift result and mutation result:
- Readback: PR state, final SHA, branch recovery, deployment and runtime proof:
- Blocked or untested work; next action:

Closure explanation: State whether obsolete, superseded, rejected, irrelevant, or unconfirmed; cite evidence and replacement where present. Include original head/branch recovery references. State that only the PR was closed. Do not claim unconfirmed work was proven unnecessary.

Output row: Repository | PR | Objective (<60 words) | Evidence | Disposition | Repair requirements | Production impact | Verified result
